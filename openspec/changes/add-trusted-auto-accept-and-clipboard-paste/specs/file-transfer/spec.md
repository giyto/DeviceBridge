## MODIFIED Requirements

### Requirement: Browser upload сохраняется только в выбранное Android location

До приёма Browser → Android payload пользователь MUST подтвердить предложение, за единственным исключением: offer от session, созданной из действующего trusted browser credential, MUST приниматься без ручного подтверждения, когда пользователь включил автоприём и сохранённая default destination доступна. Destination MUST быть либо ранее выбранной доступной default folder с действующим persistable SAF permission, либо папкой, явно выбранной через системный picker для текущего решения. Выданный доступ MUST быть ограничен выбранным location; широкое storage permission MUST NOT запрашиваться. Автоприём MUST NOT ослаблять проверки размера, MIME type, имени, checksum и очереди, которые действуют для ручного подтверждения.

#### Scenario: Android подтверждает входящие файлы
- **WHEN** browser предлагает один или несколько допустимых файлов, а автоприём к этой session не применяется
- **THEN** Android показывает sender, metadata и доступную destination либо действие выбора папки
- **AND** server начинает принимать payload только после явного подтверждения

#### Scenario: Доступна папка по умолчанию
- **WHEN** browser предлагает допустимые files, сохранённая default destination доступна, а автоприём к этой session не применяется
- **THEN** Android показывает эту destination вместе с offer и действиями подтверждения или изменения папки
- **AND** payload не принимается до явного подтверждения пользователя

#### Scenario: Автоприём от запомненного браузера
- **WHEN** автоприём включён, default destination доступна и trusted session предлагает допустимые files
- **THEN** каждый item принимается в default destination без ручного подтверждения по мере продвижения очереди
- **AND** Android показывает, что item принят автоматически, и имя браузера-отправителя

#### Scenario: Приложение не на экране
- **WHEN** автоприём применяется к offer, а DeviceBridge свёрнут или экран телефона выключен при работающем сервере
- **THEN** приём начинается без открытия приложения
- **AND** результат передачи и запись истории совпадают с результатом ручного подтверждения

#### Scenario: Обычная session не использует автоприём
- **WHEN** browser подключён без запоминания и предлагает files при включённом автоприёме
- **THEN** каждый offer ожидает явного подтверждения пользователя
- **AND** настройка автоприёма не меняет поведение этой session

#### Scenario: Автоприём не может использовать папку
- **WHEN** автоприём включён, но default destination отсутствует или стала недоступна
- **THEN** offer не начинает payload и переходит к ручному подтверждению с понятной причиной
- **AND** item не теряется и не получает completed или failed только из-за недоступной папки

#### Scenario: Доверие отозвано до начала приёма
- **WHEN** trusted browser отозван, пока его offers находятся в очереди
- **THEN** ни один ещё не начатый item этой session не принимается автоматически
- **AND** состояние очереди определяется существующими правилами отзыва session

#### Scenario: Папка по умолчанию отсутствует
- **WHEN** пользователь принимает offer без доступной default destination
- **THEN** Android открывает системный folder picker до начала payload
- **AND** queued uploads получают destination только после успешного результата picker

#### Scenario: Пользователь отменяет выбор папки
- **WHEN** системный picker закрыт без результата
- **THEN** предложение не начинает передачу и ранее сохранённая допустимая destination не очищается
- **AND** browser получает понятное состояние ожидания нового решения или отмены

#### Scenario: Пользователь меняет destination для offer
- **WHEN** пользователь выбирает другую доступную папку для текущего предложения
- **THEN** Android использует подтверждённую папку для этого batch
- **AND** обновляет default destination только после отдельного явного согласия пользователя

#### Scenario: Папка стала недоступна
- **WHEN** provider отзывает доступ либо output stream не может быть открыт
- **THEN** transfer не начинает payload или завершается контролируемой ошибкой
- **AND** приложение предлагает повторно выбрать location без crash
