## Why

Два самых частых повседневных сценария DeviceBridge требуют лишних действий. Каждый входящий файл Browser → Android подтверждается на телефоне отдельно, поэтому пачка из десятков файлов со своего компьютера превращается в серию однотипных нажатий. Скриншот с компьютера нельзя отправить сразу: его приходится сначала сохранить в файл и затем выбрать в диалоге.

## What Changes

- Добавить Android-настройку «Автоматически принимать файлы от запомненных браузеров», выключенную по умолчанию и доступную только при выбранной доступной папке для входящих.
- При включённой настройке входящие files от session, созданной из trusted browser credential, принимаются в папку по умолчанию без ручного подтверждения, в том числе когда приложение свёрнуто, а сервер работает в foreground service.
- Обычные (одноразовые) sessions по-прежнему требуют явного подтверждения каждого offer; лимит размера, MIME и остальная validation не меняются.
- Отзыв доверия, выключение настройки или недоступность папки прекращают автоприём; offer возвращается к ручному подтверждению без потери и без ложного terminal success.
- Android явно показывает, что файл принят автоматически, и от какого браузера.
- В web shell добавить вставку изображения из буфера обмена (`Ctrl+V`) в file draft как третий источник наравне с file input и drag-and-drop, с автоматическим понятным именем файла и прежним обязательным подтверждением отправки.
- Вставка текста в поле сообщения работает как раньше; изображение, вставленное в это поле, добавляется в file draft с подсказкой.

Вне scope: кнопка «Принять все» для одноразовых sessions, изменение protocol version, изменение схемы истории, сигналы о входящем в браузере и чтение буфера без явной вставки пользователем.

## Capabilities

### New Capabilities

- Нет.

### Modified Capabilities

- `file-transfer`: требование о явном подтверждении Browser → Android offer дополняется исключением для trusted sessions при включённом автоприёме.
- `local-history-and-settings`: настройки дополняются локальным флагом автоприёма с правилами доступности и значением по умолчанию.
- `browser-web-interface`: file draft получает источник «вставка изображения из буфера обмена».

## Impact

- Android: `DeviceSettings` и DataStore (новый ключ), Settings UI, новый service-level компонент автоприёма рядом с `FileTransferCoordinator`, использование `PersistedDestinationPermissionController` и `FileDestinationLeaseRegistry` вне Compose, отображение источника принятия на экранах «Файлы» и «Главная».
- Web: обработчик `paste` в file transfer view, генерация имени файла, подсказка в зоне файлов, тесты Vitest и Playwright.
- Protocol, persistence schema истории, web asset policy и CSP не меняются.
- Безопасность: автоприём ограничен trusted sessions и явно включённой настройкой; вставка из буфера использует только явный жест пользователя и не требует secure context.
