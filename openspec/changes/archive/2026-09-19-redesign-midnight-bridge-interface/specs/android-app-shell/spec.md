## MODIFIED Requirements

### Requirement: Android shell использует единую визуальную систему DeviceBridge

Android UI MUST использовать согласованную систему `Midnight Bridge / Porcelain Bridge`: semantic design tokens для light/dark colors, typography, spacing по сетке 4/8, shape, border, elevation и status meanings. Тёмная тема MUST использовать спокойную near-black/graphite основу с ограниченным сине-фиолетовым accent, а светлая — холодный нейтральный фон и белые рабочие surfaces без чисто белого page background. Primary, secondary и destructive actions MUST иметь стабильную иерархию и состояния default, pressed, focused, disabled, loading, error и success. Визуальная система MUST сохранять Material platform conventions, MUST NOT зависеть от внешних ресурсов и MUST NOT использовать glow, blur или motion как единственный признак состояния.

#### Scenario: Пользователь переключает системную тему

- **WHEN** системная тема меняется между светлой и тёмной
- **THEN** все top-level screens используют соответствующие Midnight или Porcelain surfaces, typography и status colors без вспышки неподходящей темы
- **AND** status, border и focus остаются понятными без опоры только на цвет

#### Scenario: Primary action временно недоступен

- **WHEN** действие нельзя выполнить из-за loading, отсутствия session или незавершённой validation
- **THEN** control имеет понятный disabled state и сохраняет label
- **AND** рядом доступно краткое объяснение причины, если она не очевидна из контекста

#### Scenario: Системная анимация уменьшена

- **WHEN** Android сообщает уменьшенный или отключённый animation scale
- **THEN** декоративный Signal Flow feedback сокращается или становится статическим
- **AND** изменение connection или transfer state остаётся немедленно понятным по тексту и semantics

## ADDED Requirements

### Requirement: Исходное имя соответствует Android-устройству

При отсутствии сохранённого пользовательского имени Android app MUST формировать исходное device name из доступных производителя и модели текущего устройства, нормализовать повтор производителя, управляющие символы и ограничение длины и показывать результат в Settings. Точное сохранённое legacy-значение `DeviceBridge Android` MUST считаться прежним стандартным значением и MUST мигрировать в физическое имя; любое другое сохранённое пользователем допустимое имя MUST иметь приоритет и MUST NOT перезаписываться при запуске или обновлении приложения. Эффективное имя MUST быть доступно авторизованному browser session через status contract без промежуточной публикации generic legacy-default.

#### Scenario: Приложение впервые запущено на телефоне

- **WHEN** DataStore ещё не содержит пользовательское device name, а Android сообщает производителя и модель
- **THEN** поле имени в Settings содержит нормализованное реальное название устройства
- **AND** одинаковый manufacturer в начале model не дублируется

#### Scenario: Пользователь уже изменил имя

- **WHEN** DataStore содержит допустимое пользовательское device name
- **THEN** приложение использует сохранённое значение независимо от Build manufacturer/model
- **AND** это же effective name получает только авторизованный browser status

#### Scenario: Обновление со старого стандартного имени

- **WHEN** DataStore содержит точное legacy-значение `DeviceBridge Android`, а Android сообщает допустимые manufacturer и model
- **THEN** Settings и авторизованный browser status используют нормализованное физическое имя
- **AND** остальные настройки, выбранная папка и trusted browser data не изменяются

### Requirement: Android screens используют спокойную premium-композицию

Home, Text, Files, History и Settings SHALL использовать единый content rhythm, ограниченное количество уровней surfaces и предсказуемое расположение primary actions. Home, History и Settings MUST показывать основной заголовок без декоративной eyebrow-подписи и без повторяющего локальную модель supporting text; заголовок фильтров History MUST сохраняться без декоративного пояснения. Декоративная вложенность карточек MUST быть исключена, а мотив Signal Flow MAY применяться только для краткого объяснения активной связи или передачи. Редизайн MUST сохранять все существующие команды, drafts, operation identifiers, navigation destinations и recovery actions.

#### Scenario: Открыт верхний уровень Android-экрана

- **WHEN** пользователь открывает Home, History или Settings
- **THEN** UI показывает основной заголовок экрана без eyebrow-подписи и повторяющего пояснения о локальности
- **AND** функциональные заголовки, status text, filters и actions остаются доступны и сохраняют прежнее поведение

#### Scenario: Home показывает активную связь

- **WHEN** server запущен и browser session активна
- **THEN** connection state, browser identity и основные действия образуют первый визуальный уровень
- **AND** декоративный connection indicator не вытесняет address, pairing или active transfer information

#### Scenario: Text или Files содержат плотное содержимое

- **WHEN** feed содержит длинные URL, несколько transfer items или длинные filenames
- **THEN** surfaces сохраняют выравнивание, читаемость и применимые actions без лишних вложенных карточек
- **AND** изменение внешнего вида не меняет порядок или идентичность пользовательских операций

#### Scenario: History или Settings открыты в служебном состоянии

- **WHEN** экран показывает loading, empty, save-in-progress или recoverable error
- **THEN** визуальная иерархия остаётся согласованной с рабочим content state
- **AND** primary action остаётся один и не конкурирует с secondary controls
### Requirement: History использует одну карточку на строку и список фильтров

Android History MUST отображать записи последовательной вертикальной лентой по одной скруглённой карточке на строку и MUST NOT превращать записи в двухколоночную или квадратную grid-композицию. Файловая карточка MUST показывать тип и результат, полное доступное имя с корректным переносом, размер, время и направление передачи, сохраняя открытие деталей и удаление. Основной экран MUST заменять горизонтальные filter chips одной компактной кнопкой с количеством активных условий; нажатие MUST открывать modal bottom sheet с вертикальными группами «Направление», «Тип» и «Результат». Выбор MUST использовать существующий `HistoryFilter`, сохраняться через текущий ViewModel/SavedStateHandle и предоставлять доступные действия сброса и закрытия без новой business logic.

#### Scenario: История содержит файловые записи

- **WHEN** пользователь открывает History с одной или несколькими файловыми записями
- **THEN** каждая запись занимает отдельную строку и отображается в скруглённой карточке на всю доступную ширину
- **AND** имя файла, размер, время, направление, результат, просмотр деталей и удаление остаются читаемыми и доступными при длинном имени и font scale 200 процентов

#### Scenario: Пользователь открывает список фильтров

- **WHEN** пользователь активирует кнопку «Фильтры»
- **THEN** открывается modal bottom sheet с вертикальными selectable rows для направления, типа и результата
- **AND** каждый выбранный пункт имеет check semantics, а основная кнопка показывает количество активных условий

#### Scenario: Пользователь сбрасывает фильтры

- **WHEN** в sheet выбран хотя бы один фильтр и пользователь нажимает «Сбросить»
- **THEN** все наборы `HistoryFilter` очищаются через существующий state flow
- **AND** экран возвращается к полному списку без удаления history records или изменения их порядка

### Requirement: Тап вне поля закрывает Android-клавиатуру без потери данных

Android app MUST закрывать экранную клавиатуру и снимать focus с активного текстового поля при обычном нажатии по свободной неинтерактивной области текущего экрана. Такое действие MUST сохранять введённый draft и текущее значение настройки, MUST NOT отправлять форму, менять navigation или запускать повторную команду. Интерактивные controls и scroll gestures MUST сохранять собственное поведение; системная кнопка Back MUST продолжать закрывать клавиатуру стандартным способом.

#### Scenario: Пользователь закрывает клавиатуру свободным тапом

- **WHEN** поле отправки текста или имени устройства имеет focus, клавиатура открыта и пользователь нажимает по свободной области экрана
- **THEN** focus очищается и клавиатура закрывается
- **AND** введённое значение остаётся в draft или форме без автоматической отправки либо сохранения

#### Scenario: Пользователь нажимает действие при открытой клавиатуре

- **WHEN** клавиатура открыта и пользователь нажимает доступную кнопку, карточку или navigation control
- **THEN** control выполняет своё исходное действие ровно один раз
- **AND** общий keyboard-dismiss behavior не перехватывает click и не создаёт повторную operation
