## 1. Android: имя в сети (mDNS)

- [x] 1.1 Реализовать `MdnsCodec`: разбор запросов (вопросы, бит QU, записи в секциях answer и authority) и сборку ответов A, NSEC «нет AAAA», проб и goodbye. Защиты: пакет до 9000 байт, указатели сжатия только назад и не больше 16 переходов, ограниченное число записей. Проверка: JVM-тесты на эталонных байтах (запрос Windows A+AAAA, legacy unicast, QU), на регистронезависимое сравнение имени и на отказ без исключения для обрезанных пакетов, петель сжатия и огромных счётчиков
- [x] 1.2 Реализовать `LocalNameResponder` поверх транспорта-интерфейса и часов. Что он делает:
  - проверяет имя тремя пробами по 250 мс и перебирает суффиксы `-2`…`-9` при конфликте;
  - по правилу RFC 6762 §8.2 решает, кто уступает при одновременной пробе;
  - делает 2 объявления после проверки;
  - отвечает многоадресно не чаще раза в секунду на запись, и одноадресно на QU и legacy-запросы;
  - игнорирует запросы вне своей подсети;
  - при конфликте во время работы перестаёт отвечать;
  - при остановке отправляет goodbye.

  Проверка: JVM-тесты с поддельным транспортом и часами на каждое правило, включая «все имена заняты»
- [x] 1.3 Реализовать Android-транспорт на `MulticastSocket`:
  - `SO_REUSEADDR` до bind на 5353, привязка к интерфейсу endpoint, вход в группу 224.0.0.251;
  - `MulticastLock` на время работы;
  - разрешение `CHANGE_WIFI_MULTICAST_STATE` в манифесте;
  - обновлённые `ServerManifestContractTest` и `ServerManifestInstrumentedTest`.

  Проверка: контрактные тесты манифеста и instrumented-тест на эмуляторе API 37: тестовый клиент на том же интерфейсе отправляет запрос A и получает адрес сервера, а после остановки получает goodbye
- [x] 1.4 Встроить ответчик в `KtorServerRuntime`:
  - порядок запуска: IP → проверка имени → `prepareTls(ip, name)` → слушатели → объявление;
  - goodbye и освобождение lock при любой остановке;
  - если сокет не открылся, сервер работает по IP со статусом `Unavailable(NETWORK)`.

  Проверка: JVM-тесты runtime с поддельным ответчиком: имя занято, недоступно, конфликт во время работы, остановка из-за смены сети отзывает имя

## 4. Android: сертификаты

- [x] 4.1 Новые корни с permitted dNSName `local` в `X509Profiles.nameConstraints()`. Проверка: JVM-тест `CertPathValidator` с включённой проверкой name constraints:
  - сертификаты для `nikita.local` и `devicebridge-2.local` принимаются;
  - `example.com`, `local.example.com` и публичный IP отклоняются
- [x] 4.2 Разборщик permitted dNSName из расширения NameConstraints корня и `LocalCertificateAuthority.permits(name)`. Сертификат сервера содержит IP и занятое имя (без безусловного `devicebridge.local`), а `covers(ip, name)` проверяет оба значения. Проверка: JVM-тесты:
  - старый корень допускает только `devicebridge.local`, новый допускает любое `.local`;
  - смена имени перевыпускает сертификат сервера, а тот же IP и имя его не перевыпускают
- [x] 4.3 В защищённом режиме имя, которое корень не допускает, не занимается (`Unavailable(CERTIFICATE)`), а раздел «Защищённое соединение» показывает подсказку сбросить сертификат. Проверка: JVM-тест runtime со старым корнем и именем `nikita` и Compose-тест подсказки
