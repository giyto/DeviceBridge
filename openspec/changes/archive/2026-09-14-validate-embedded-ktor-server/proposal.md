# Change: Проверить встроенный Ktor-сервер на Android

## Why

ТЗ DeviceBridge 2.0 фиксирует одно Android-приложение: телефон поднимает локальный HTTP/WebSocket-сервер, а компьютер подключается к нему обычным браузером. До разработки пользовательских функций необходимо доказать, что выбранный серверный стек стабильно работает на минимальной поддерживаемой версии Android API 29 и на основной тестовой версии API 37.1, передаёт большие данные потоково и не создаёт неприемлемый расход памяти или размер APK.

## What Changes

- Добавить изолированный диагностический прототип встроенного сервера на Ktor 3.5.2 с engine CIO как первым проверяемым кандидатом.
- Добавить только для debug-сборки экран управления spike: запуск, остановка, повторный запуск, состояние, адрес, порт и понятная ошибка.
- Добавить защищённые диагностическим токеном маршруты /diagnostics/health, /diagnostics/ws, /diagnostics/upload и /diagnostics/download. Они не являются будущим публичным API /api/v1.
- Проверить доступ к серверу с компьютера, жизненный цикл, HTTP, WebSocket, потоковую передачу 500 МБ, отмену операции и освобождение ресурсов.
- Зафиксировать измерения памяти и изменение размера APK по воспроизводимой методике.
- Выполнить одинаковую матрицу проверок на AVD API 29 и API 37.1; на API 37.1 отдельно проверить разрешение ACCESS_LOCAL_NETWORK.
- Оформить отчёт с одним итоговым решением: accept — Ktor/CIO допускается к следующему этапу, либо replace — серверный adapter необходимо заменить до продолжения разработки.

## Capabilities

### New Capabilities

- embedded-server-viability: воспроизводимая проверка жизнеспособности встроенного локального Ktor-сервера на поддерживаемых Android API.

### Modified Capabilities

- Нет. Пользовательское поведение основного Android shell и будущий протокол /api/v1 этим change не изменяются.

## Impact

- Gradle: диагностические зависимости Ktor Server, CIO, WebSockets и kotlinx.serialization.
- Android debug source set: диагностический UI, manifest-разрешения, server adapter и тестовые маршруты.
- Тесты: JVM-тесты для детерминированных компонентов и instrumented-тесты для реального Android runtime.
- Документация: отчёт docs/spikes/embedded-ktor-server.md с командами, окружением, метриками и вердиктом.
- Release-сборка не должна содержать диагностический экран, токен или маршруты /diagnostics/*.
- В change не входят production lifecycle/foreground service, постоянная авторизация браузера, история, передача пользовательских данных и веб-интерфейс.
