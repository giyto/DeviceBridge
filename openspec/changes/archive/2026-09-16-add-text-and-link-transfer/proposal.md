## Why

После защищённого подключения DeviceBridge должен начать решать основную ежедневную задачу: передавать текст и ссылки между Android-телефоном и браузером компьютера без облака и отдельного desktop-приложения. Одновременно нужно устранить вводящую в заблуждение метку клиента: Яндекс Браузер содержит Chromium-признаки и сейчас ошибочно отображается как Chrome.

## What Changes

- Добавить двустороннюю передачу UTF-8 текста и HTTP(S)-ссылок между Android и конкретной активной browser session с явным подтверждением отправки.
- Опубликовать защищённый `POST /api/v1/text` и события `/api/v1/events` с версионированными DTO, подтверждениями, ограничением 100 КБ и идемпотентностью по `messageId`.
- Добавить Android-экран отправки текста, обработку `ACTION_SEND` для `text/plain`, входящие карточки и явные действия копирования/открытия ссылки без скрытого чтения clipboard.
- Добавить web-форму отправки, ленту входящих элементов текущей сессии, безопасный текстовый вывод и fallback ручного копирования, когда Clipboard API недоступен.
- Распознавать Яндекс Браузер по собственному runtime-признаку до общего Chromium/Chrome fallback; неизвестные или неоднозначные клиенты показывать нейтрально, не выдавая метаданные браузера за доказательство личности.
- Оставить передачу файлов, постоянную историю, trusted browsers и автоматическое открытие ссылок за границами этого change.

## Capabilities

### New Capabilities

- `text-and-link-transfer`: протокол, ограничения, состояния и пользовательские сценарии двусторонней передачи текста и безопасных ссылок в текущей авторизованной сессии.

### Modified Capabilities

- `android-app-shell`: разблокировать действие «Текст», добавить экран отправки и входящие элементы, а также показывать корректную безопасную метку браузера.
- `browser-web-interface`: включить текстовую форму и ленту текущей сессии, fallback копирования и точное распознавание Яндекс Браузера до общего Chrome fallback.
- `secure-browser-session`: нормализовать и ограничить информационную browser label, сохраняя её недоверенным session metadata.
- `server-lifecycle`: включить только завершённые text routes и text events в production allowlist, оставив file API закрытым.

## Impact

- Android: новые domain-модели и use cases передачи текста, repository-контракт, ViewModel/Compose UI, `ACTION_SEND` entry point и адаптер embedded server.
- Protocol/API: `POST /api/v1/text` и текстовые WebSocket events/acknowledgements под существующей session authorization.
- Web: TypeScript-логика текстовой формы, session feed, безопасного копирования и определения browser label.
- Tests: unit-тесты протокола, идемпотентности и URL-классификации; server integration, Compose и Vitest-сценарии, включая Яндекс Браузер.
- Новые внешние backend, платные сервисы, desktop-приложение и обязательные runtime-зависимости не добавляются.
