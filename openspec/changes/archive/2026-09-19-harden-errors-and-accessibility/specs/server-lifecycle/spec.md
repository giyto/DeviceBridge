## ADDED Requirements

### Requirement: Server lifecycle сообщает точную причину и допустимое восстановление

Каждый неуспешный запуск и вынужденная остановка server lifecycle MUST иметь различимую user-facing причину и применимое действие: повторить запуск, выдать local-network permission, открыть системные настройки, подключиться к локальной сети либо использовать новый опубликованный адрес. Generic network error MUST NOT скрывать отказ разрешения, отсутствие достижимого адреса, bind failure или смену IP.

#### Scenario: Local-network permission отклонено

- **WHEN** запуск сервера заблокирован отказом или отзывом требуемого local-network permission
- **THEN** lifecycle остаётся в Stopped с соответствующей причиной
- **AND** Android предлагает запросить разрешение повторно либо открыть настройки, если повторный системный запрос недоступен

#### Scenario: Достижимый адрес отсутствует

- **WHEN** сервер не может опубликовать допустимый Wi-Fi или hotspot endpoint
- **THEN** Android объясняет необходимость локальной сети или точки доступа
- **AND** не показывает stale адрес как рабочий

#### Scenario: Запуск не удался по внутренней причине

- **WHEN** listener не смог запуститься или освободить выбранный port в установленный timeout
- **THEN** lifecycle переходит в terminal failure текущей попытки и освобождает частично созданные ресурсы
- **AND** пользователь может явно выполнить новый запуск без перезапуска приложения

### Requirement: Recovery не переносит старый endpoint или session

После потери сети, смены IP, server stop или failed generation DeviceBridge MUST признать прежний endpoint недействительным, завершить принадлежащие ему browser sessions и не запускать новый server generation автоматически. Новый endpoint SHALL публиковаться только после явного запуска пользователя и успешного определения актуального адреса.

#### Scenario: IP изменился во время работы

- **WHEN** активный локальный IP больше не соответствует опубликованному endpoint
- **THEN** server generation завершается, sessions отзываются и UI показывает причину «адрес изменился»
- **AND** старый адрес не используется для reconnect instructions

#### Scenario: Пользователь повторно запускает сервер

- **WHEN** после устранения причины пользователь явно выбирает запуск
- **THEN** lifecycle создаёт новый generation и публикует только актуальный endpoint и pairing code
- **AND** drafts могут остаться в UI, но прошлые session tokens и операции не восстанавливаются
