## ADDED Requirements

### Requirement: Главный экран показывает browser pairing

Во время Running Android-приложение MUST показывать действующий одноразовый код с оставшимся временем, pending pairing requests и фактические активные browser sessions. Код и session-сведения MUST исчезать при завершении server lifecycle.

#### Scenario: Сервер ожидает подключение браузера

- **WHEN** production server работает и активных browser sessions нет
- **THEN** главный экран показывает шестизначный pairing code, срок его действия и краткую инструкцию для компьютера
- **AND** не показывает фиктивный подключённый browser client

#### Scenario: На телефоне ожидается решение

- **WHEN** browser client правильно ввёл код и создал pending request
- **THEN** Android UI показывает browser label, source IPv4 и действия «Разрешить» и «Отклонить»
- **AND** доступное название каждого действия однозначно относится к этому запросу

#### Scenario: Browser session активна

- **WHEN** пользователь разрешил подключение
- **THEN** главный экран показывает browser client в списке подключённых и предоставляет действие отключения
- **AND** число браузеров совпадает с фактическим session state

#### Scenario: Сервер остановлен

- **WHEN** server lifecycle покидает Running
- **THEN** главный экран не показывает прежний pairing code, countdown, pending requests или active sessions

## MODIFIED Requirements

### Requirement: Недоступность передачи без активной сессии

Android-приложение MUST блокировать действия «Текст» и «Файлы», пока соответствующие transfer capabilities не реализованы отдельными changes. Интерфейс MUST различать отсутствие запущенного сервера, отсутствие авторизованного браузера и временную недоступность ещё не реализованных операций.

#### Scenario: Действия при остановленном сервере

- **WHEN** пользователь находится на главном экране в состоянии «Сервер остановлен»
- **THEN** действия «Текст» и «Файлы» отображаются недоступными
- **AND** интерфейс сообщает, что сначала потребуется запустить сервер и подключить браузер

#### Scenario: Сервер запущен без авторизованного браузера

- **WHEN** production server работает, но ни один browser client не авторизован
- **THEN** действия «Текст» и «Файлы» остаются недоступными
- **AND** интерфейс предлагает завершить pairing с браузером

#### Scenario: Browser авторизован до реализации transfer

- **WHEN** хотя бы одна browser session подключена, но change передачи текста или файлов ещё не реализован
- **THEN** соответствующие действия остаются недоступными
- **AND** интерфейс честно сообщает, что подключение выполнено, а передача появится на следующем этапе
