## MODIFIED Requirements

### Requirement: Сервер работает только в явно запущенной пользовательской сессии

DeviceBridge MUST запускать production server только после явного действия пользователя и MUST NOT автоматически запускать его после загрузки телефона, запуска приложения, появления сети, восстановления процесса или автоостановки. Явным действием считается выбор запуска на видимом экране DeviceBridge или нажатие плитки DeviceBridge в быстрых настройках Android.

#### Scenario: Пользователь запускает сервер

- **WHEN** пользователь на видимом экране DeviceBridge выбирает «Запустить DeviceBridge»
- **THEN** система проверяет необходимые условия и запускает server lifecycle
- **AND** состояние проходит через «Запускается» к «Сервер запущен» либо к понятной ошибке

#### Scenario: Пользователь запускает сервер плиткой

- **WHEN** сервер остановлен, телефон разблокирован, необходимые разрешения выданы и пользователь нажимает плитку DeviceBridge
- **THEN** система запускает тот же server lifecycle без открытия приложения, если Android допускает запуск foreground service
- **AND** плитка и уведомление проходят через «Запускается» к «Сервер запущен» либо показывают понятную ошибку

#### Scenario: Повторная команда запуска

- **WHEN** команда запуска повторяется во время запуска или работы сервера
- **THEN** система сохраняет единственный server instance и единственный listening socket
- **AND** не создаёт дублирующее уведомление

#### Scenario: Сеть появилась без действия пользователя

- **WHEN** сервер остановлен и на телефоне появляется подходящая локальная сеть
- **THEN** система может обновить доступность запуска
- **AND** сервер остаётся остановленным до явной команды пользователя

#### Scenario: Телефон перезагружен

- **WHEN** телефон завершает загрузку системы
- **THEN** DeviceBridge не запускает server service автоматически

## ADDED Requirements

### Requirement: Плитка быстрых настроек отражает и переключает состояние сервера

DeviceBridge MUST предоставлять плитку быстрых настроек Android. Плитка MUST показывать фактическое состояние того же server lifecycle, что и главный экран: активна при работающем сервере с числом подключённых браузеров, неактивна при остановленном сервере или ошибке, недоступна для нажатия во время запуска и остановки. Нажатие MUST запускать остановленный сервер или останавливать работающий. Плитка MUST NOT запускать сервер при заблокированном телефоне без разблокировки и MUST NOT обходить запрос необходимых разрешений.

#### Scenario: Плитка отражает работающий сервер

- **WHEN** сервер работает, запущенный с главного экрана или плиткой
- **THEN** плитка активна и показывает «Запущен» и число подключённых браузеров
- **AND** после остановки любым способом плитка становится неактивной и показывает «Остановлен»

#### Scenario: Нужны разрешение или видимый экран

- **WHEN** пользователь нажимает плитку, а необходимое разрешение локальной сети не выдано либо Android запрещает запуск foreground service без видимого экрана
- **THEN** система сворачивает шторку и открывает DeviceBridge
- **AND** приложение запрашивает недостающее разрешение и продолжает запуск на видимом экране как продолжение того же явного действия

#### Scenario: Телефон заблокирован

- **WHEN** пользователь нажимает плитку остановленного сервера на заблокированном телефоне
- **THEN** система просит разблокировать телефон
- **AND** сервер запускается только после успешной разблокировки

#### Scenario: Остановка плиткой без активных передач

- **WHEN** сервер работает, незавершённых text и file operations нет и пользователь нажимает плитку
- **THEN** сервер останавливается так же, как действием «Остановить» в уведомлении
- **AND** плитка становится неактивной

#### Scenario: Остановка плиткой во время передачи

- **WHEN** пользователь нажимает плитку, пока идёт text или file operation
- **THEN** система показывает подтверждение, что передача будет прервана
- **AND** сервер останавливается только после подтверждения, а при отказе продолжает работать без изменений

#### Scenario: Пользователь добавляет плитку

- **WHEN** на Android 13 или новее пользователь выбирает в Settings добавление плитки
- **THEN** система показывает стандартный запрос добавления плитки DeviceBridge
- **AND** на более старых версиях Settings объясняет, как добавить плитку вручную

### Requirement: Сервер автоматически останавливается без подключений

Если автоостановка включена, DeviceBridge MUST останавливать работающий сервер, когда в течение выбранного времени одновременно выполняются условия простоя: ни один браузер не держит живое подключение к серверу, нет ожидающего запроса pairing и нет незавершённых text или file operations. Отсчёт MUST начинаться заново при появлении любого из этих условий активности. Время MUST измеряться монотонными часами, включая время сна устройства. Автоостановка MUST проходить тем же путём, что и остановка пользователем: отменять ресурсы, завершать sessions и удалять foreground-уведомление. Её причина MUST быть отличима от ошибки.

#### Scenario: Браузеры не подключались

- **WHEN** сервер запущен, автоостановка равна 30 минутам и за 30 минут ни один браузер не подключился
- **THEN** сервер останавливается с причиной «нет подключений»
- **AND** главный экран показывает «Сервер остановлен» с пояснением «Остановлен автоматически: 30 минут без подключений» как обычное состояние Stopped с действием запуска, а не как ошибку

#### Scenario: Браузер закрыл вкладку

- **WHEN** единственный подключённый браузер закрыл вкладку, и его session всё ещё не отозвана
- **THEN** отсчёт простоя начинается с момента потери живого подключения
- **AND** сервер останавливается через выбранное время, если браузер не подключится снова

#### Scenario: Браузер подключён, но бездействует

- **WHEN** браузер держит живое подключение и ничего не передаёт
- **THEN** сервер не останавливается автоматически
- **AND** отсчёт не идёт

#### Scenario: Идёт длинная передача

- **WHEN** выполняется file или text operation либо ожидает решения pairing request
- **THEN** сервер не останавливается автоматически, даже если выбранное время истекло бы
- **AND** отсчёт начинается после завершения операции и потери последнего подключения

#### Scenario: Телефон спал

- **WHEN** выбранное время простоя истекло, пока телефон находился в сне
- **THEN** сервер останавливается при ближайшем пробуждении процесса
- **AND** остановка не откладывается на полный интервал после пробуждения

#### Scenario: Уведомление показывает отсчёт

- **WHEN** условия простоя выполняются и отсчёт идёт
- **THEN** foreground-уведомление показывает время, когда сервер остановится без подключений
- **AND** при появлении подключения эта строка исчезает

#### Scenario: Автоостановка выключена

- **WHEN** пользователь выключил автоостановку
- **THEN** сервер работает до явной остановки пользователем или системной причины
- **AND** уведомление не показывает время остановки
