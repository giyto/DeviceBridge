## ADDED Requirements

### Requirement: Страница ждёт телефон и подключается сама

Если телефон недоступен при открытии страницы или стал недоступен во время работы и ограниченные попытки восстановления исчерпаны, web shell MUST перейти в состояние ожидания телефона вместо окончательной остановки попыток. В ожидании страница MUST проверять доступность только через публичный `GET /web-manifest.json`: не чаще одного раза в 3 секунды, пока вкладка видна, и не чаще одного раза в 15 секунд, пока она скрыта. Возвращение вкладки на экран, событие `online` и кнопка «Проверить сейчас» MUST запускать проверку сразу. Когда телефон снова доступен, страница MUST начать новый цикл подключения. Если сохранён запомненный вход, она MUST обменять его на новую session без кода. Если запомненного входа нет, она MUST показать форму кода с пометкой, что телефон снова доступен. Ожидание MUST NOT отправлять pairing code, повторять передачу текста или файлов и MUST сохранять черновики. Ожидание MUST продолжаться, пока вкладка открыта.

#### Scenario: Сервер снова запущен при открытой вкладке

- **WHEN** вкладка с запомненным входом ждёт телефон, а пользователь запускает сервер
- **THEN** не позднее чем через 3 секунды после того, как сервер начал отвечать, видимая вкладка подключается без кода
- **AND** черновики текста и файлов сохраняются

#### Scenario: Страница открыта, пока сервер выключен

- **WHEN** пользователь открывает закладку, пока сервер на телефоне выключен
- **THEN** страница показывает «Телефон недоступен», объясняет, что подключится сама после запуска сервера, и продолжает ждать
- **AND** после запуска сервера подключается без перезагрузки страницы

#### Scenario: Запомненного входа нет

- **WHEN** телефон снова доступен, а запомненного входа у браузера нет
- **THEN** страница показывает форму кода с пометкой «Телефон снова доступен»
- **AND** не отправляет код автоматически

#### Scenario: Вкладка скрыта

- **WHEN** вкладка в ожидании скрыта
- **THEN** проверки выполняются не чаще одного раза в 15 секунд
- **AND** при возвращении вкладки на экран проверка выполняется сразу

### Requirement: Страница подсказывает установить её как приложение

После успешного подключения по адресу с именем `.local` в Chrome или Edge web shell MUST один раз показать закрываемую подсказку. Подсказка объясняет, как установить страницу как приложение со своей иконкой, и содержит инструкцию для этого браузера. Подсказка MUST NOT показываться, если страница уже открыта как установленное приложение, открыта по IP-адресу или в другом браузере. Закрытие подсказки MUST запоминаться в хранилище браузера. Если хранилище недоступно, подсказка MUST NOT мешать работе. Подсказка MUST NOT регистрировать service worker или web app manifest.

#### Scenario: Первый вход по имени в Edge

- **WHEN** пользователь впервые подключился по `http://devicebridge.local:8787` в Edge
- **THEN** страница показывает подсказку с инструкцией для Edge и кнопкой закрытия

#### Scenario: Подсказка закрыта

- **WHEN** пользователь закрыл подсказку и позже снова открыл страницу
- **THEN** подсказка больше не показывается

#### Scenario: Страница открыта по IP-адресу

- **WHEN** пользователь подключился по адресу с IPv4
- **THEN** подсказка не показывается

## MODIFIED Requirements

### Requirement: Страница честно отображает доступность локального web server

Web shell MUST проверять доступность совместимой версии локального web server через публичный same-origin `GET /web-manifest.json`. Manifest MUST считаться web asset, содержать только версии протокола и web assets и MUST NOT содержать токены, идентификаторы устройства или другие секреты. После pairing фактический session status MUST загружаться только через защищённый `GET /api/v1/status`.

#### Scenario: Локальный web server доступен

- **WHEN** `/web-manifest.json` возвращает успешный совместимый ответ без session token
- **THEN** страница показывает, что DeviceBridge доступен для pairing
- **AND** отображает версию протокола и версию web assets без приватного состояния

#### Scenario: Статус недоступен

- **WHEN** запрос manifest завершается сетевой ошибкой, timeout или несовместимым ответом
- **THEN** страница показывает понятное состояние потери соединения
- **AND** после ограниченного быстрого retry переходит в ожидание телефона с явным действием «Проверить сейчас»

#### Scenario: Неавторизованный API статуса не опубликован

- **WHEN** браузер без действующего session token запрашивает `/api/v1/status`
- **THEN** сервер возвращает `401 Unauthorized` без сведений о состоянии устройства
- **AND** публичная проверка доступности использует только `/web-manifest.json`

#### Scenario: Авторизованный status доступен

- **WHEN** подключённый browser client запрашивает `/api/v1/status` с действующим token
- **THEN** web shell показывает фактическое подключённое состояние текущей session
- **AND** не получает codes или tokens других clients

### Requirement: Web routes ограничены локальным origin

Сервер MUST проверять допустимый `Host` и, когда заголовок `Origin` присутствует, принимать только same-origin запрос. Допустимым `Host` MUST считаться только опубликованный IPv4-адрес с портом и, если телефон занял имя в сети, это имя `<имя>.local` с тем же портом. Любое другое имя, включая другие имена `.local`, MUST отклоняться. Сервер MUST NOT возвращать разрешающий сторонние origins CORS-заголовок.

#### Scenario: Same-origin запрос разрешён

- **WHEN** web asset запрошен с допустимым `Host` без `Origin` или с соответствующим same-origin `Origin`
- **THEN** сервер возвращает запрошенный ресурс
- **AND** ответ не содержит permissive CORS

#### Scenario: Запрос по имени телефона разрешён

- **WHEN** телефон занял имя `devicebridge.local`, и браузер запрашивает страницу с `Host: devicebridge.local:<порт>` и соответствующим `Origin`
- **THEN** сервер обрабатывает запрос так же, как запрос по IPv4-адресу

#### Scenario: Чужой Host или Origin отклонён

- **WHEN** запрос содержит недопустимый `Host`, включая не занятое телефоном имя `.local`, или сторонний `Origin`
- **THEN** сервер возвращает HTTP 403
- **AND** не раскрывает содержимое web asset

### Requirement: Пользователь видит ограничение локального HTTP

Если страница открыта по HTTP, web shell MUST понятным языком сообщать, что локальный HTTP не шифрует трафик, что другое устройство в той же сети может выдать себя за телефон, и что DeviceBridge следует использовать только в доверенной домашней или личной сети. Предупреждение MUST быть раскрыто при первом использовании или после сброса preference и MAY быть свёрнуто в компактную строку нажатием по всей поверхности. Та же поверхность MUST раскрывать предупреждение обратно без отдельной кнопки и без дополнительного security help/details блока. Collapse preference MUST NOT изменять network restrictions, authorization или session security. Если страница открыта по HTTPS, web shell MUST NOT показывать предупреждение о незашифрованном соединении и MUST показывать компактную пометку о том, что соединение с телефоном зашифровано, и советовать сохранить защищённую страницу в закладки.

#### Scenario: Открыта корневая страница

- **WHEN** пользователь открывает web shell по HTTP и сохранённого решения скрыть предупреждение нет
- **THEN** на странице видимо предупреждение о незашифрованном локальном соединении и о том, что в чужой сети другое устройство может выдать себя за телефон
- **AND** пользователю рекомендовано не передавать чувствительные данные через публичный или чужой Wi-Fi

#### Scenario: Пользователь сворачивает предупреждение

- **WHEN** пользователь нажимает по раскрытой поверхности предупреждения мышью, Enter или Space
- **THEN** поясняющий текст сворачивается, а compact surface сохраняет warning icon, заголовок и chevron
- **AND** control сохраняет focus, получает `aria-expanded="false"` и остаётся компактным после reload и полного перезапуска того же browser profile

#### Scenario: Пользователь раскрывает предупреждение

- **WHEN** пользователь повторно активирует компактную поверхность предупреждения
- **THEN** полный поясняющий текст появляется в той же карточке без отдельного help/details блока
- **AND** control сохраняет focus и получает `aria-expanded="true"`

#### Scenario: Страница открыта по HTTPS

- **WHEN** пользователь открывает web shell по HTTPS в защищённом режиме
- **THEN** предупреждение о незашифрованном HTTP не отображается
- **AND** видна компактная пометка «Соединение зашифровано» с советом сохранить страницу в закладки

### Requirement: Browser может явно запросить доверенное подключение

Во время pairing web shell MUST предоставлять отдельную опцию «Запомнить этот браузер», которая MUST быть включена по умолчанию и которую пользователь MAY выключить. Включённая опция только просит телефон запомнить браузер; решение о доверии MUST оставаться отдельным решением Android host. Обычный session token MUST оставаться tab-scoped; только отдельный trusted credential, выданный после явного решения Android host, MAY храниться persistent для последующего обмена на новую session.

#### Scenario: Форма кода открыта
- **WHEN** web shell показывает форму pairing code, в том числе после сброса формы
- **THEN** опция «Запомнить этот браузер» включена
- **AND** пользователь может выключить её мышью или клавиатурой до отправки кода

#### Scenario: Пользователь не запрашивает доверие
- **WHEN** pairing выполнен с выключенной опцией «Запомнить этот браузер»
- **THEN** web shell хранит только текущий session token в session storage
- **AND** после завершения server generation новый pairing требует код

#### Scenario: Android разрешил доверие
- **WHEN** pairing завершён и Android host явно разрешил запомнить browser
- **THEN** web shell сохраняет отдельный opaque trusted credential в persistent browser storage
- **AND** не сохраняет generation-scoped session token как постоянный credential

#### Scenario: Trusted reconnect успешен
- **WHEN** страница открыта при новом server generation и сохранённый credential действителен
- **THEN** web shell обменивает его через same-origin trusted-session operation на новый tab-scoped session token
- **AND** открывает подключённый интерфейс без ввода нового pairing code

#### Scenario: Credential истёк или отозван
- **WHEN** trusted-session operation возвращает недействительный, истёкший или отозванный результат
- **THEN** web shell удаляет локальный credential и показывает обычную pairing form с сообщением «Этот телефон не узнал браузер», которое называет возможные причины: браузер удалили из доверенных на телефоне, срок доверия истёк или по этому адресу отвечает другой телефон
- **AND** не повторяет запрос бесконечно и не сообщает ложное подключение

### Requirement: Web shell ограниченно восстанавливает event channel

Авторизованный web shell MUST выполнять bounded reconnect только для канала событий той же session и server generation. Во время reconnect UI MUST сохранять допустимые text и file drafts, блокировать действия, которым нужна подтверждённая session, и MUST NOT автоматически повторять pairing, text delivery, file offer, upload или download.

#### Scenario: Кратковременный разрыв восстановлен

- **WHEN** event channel временно закрывается и reconnect той же session завершается успешно в пределах установленного лимита
- **THEN** UI возвращается в connected state и получает актуальный snapshot
- **AND** ни одна пользовательская операция не создаётся и не отправляется повторно автоматически

#### Scenario: Лимит reconnect исчерпан

- **WHEN** все разрешённые reconnect attempts завершились без авторизованного соединения
- **THEN** web shell прекращает попытки восстановить канал этой session и переходит в ожидание телефона
- **AND** пользовательский draft остаётся доступным, пока вкладка не закрыта или пользователь его не очистил

#### Scenario: Session стала недействительной

- **WHEN** reconnect получает terminal session error или server generation изменился
- **THEN** web shell удаляет недействительный session token и возвращает пользователя к pairing
- **AND** trusted credential удаляется только когда сервер обозначил её истёкшей или отозванной

#### Scenario: Сервер перезапущен, пока вкладка ждала
- **WHEN** вкладка вышла из ожидания телефона, а сохранённый session token относится к завершённому server generation
- **THEN** web shell удаляет этот session token и сам обменивает запомненный вход на новую session, если он сохранён
- **AND** session, отозванная на телефоне при работающем сервере, не восстанавливается автоматически запомненным входом
