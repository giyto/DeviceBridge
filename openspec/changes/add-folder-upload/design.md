## Context

Мотивация описана в proposal.md. Здесь только текущее устройство передачи с компьютера на телефон и ограничения, из которых вытекает решение.

- **Протокол.** `POST /api/v1/files` принимает предложение до 32 файлов (`FileOfferMessage`). В каждом элементе обязателен SHA-256, поэтому страница сейчас хеширует все выбранные файлы до отправки предложения. Дальше каждый файл идёт своим путём: `upload-offset`, затем тело `POST /api/v1/files/{transferId}`, проверка суммы, `COMPLETED`. `batchId` участвует только в идемпотентности и нигде не хранится.
- **Очередь.** `FileTransferScheduler` держит один активный файл в направлении «браузер → телефон». `FileTransferCoordinator(maxItems = 100)` считает все элементы поколения сервера, включая законченные. Папка из 2000 файлов упёрлась бы в `CapacityReached`.
- **Решение на телефоне.** Каждый файл проходит `CONNECTING` и ждёт своего решения: вручную на экране передач, автоприёмом `TrustedAutoAcceptController` или через `NotificationAcceptedTransfers`. Место сохранения выдаётся арендой `FileDestinationLeaseRegistry` на одну передачу.
- **Хранение.** `ContentResolverPartialDocumentProvider` создаёт документы только в корне выбранного дерева SAF. Подпапки нигде не создаются. `SafeFilenameResolver.normalize` оставляет от имени только последнюю часть пути и ограничивает её 120 символами, `resolveCollision` добавляет « (n)» без учёта регистра.
- **Продолжение.** Для файлов от 8 МиБ незавершённая часть хранится под ключом `PartialUploadKey(sha256, sizeBytes, displayName, treeUri)` в Room (`partial_uploads`, база версии 2).
- **История и уведомления.** `FileTransferHistoryRecorder` пишет запись на каждый файл. `EventNotificationPlanner` группирует ожидающие файлы по сессии браузера в одно уведомление, итог тоже один на сессию и направление.
- **Страница.** `<input type="file" multiple>` и область перетаскивания читают только `dataTransfer.files`. Перетащенная папка приходит как один непригодный `File`.

## Goals / Non-Goals

**Goals:**
- Папка до 2000 файлов и 20 ГиБ проходит одним решением, без исчерпания очереди и без хеширования всей папки до начала.
- Протокол и код отдельных файлов остаются как есть. Файл папки — это обычная передача файла с двумя дополнительными полями.
- Путь внутри папки проверяется и очищается на телефоне независимо от того, что прислала страница.

**Non-Goals:**
- Продолжение папки после перезапуска сервера или после закрытия страницы. У страницы больше нет доступа к файлам, а у телефона нет состояния папки.
- Параллельная передача нескольких файлов папки. Скорость и так упирается в Wi-Fi.
- Одновременное хеширование следующего файла, пока передаётся текущий. Можно добавить позже, если чтение станет узким местом.

## Decisions

### 1. Заявка папки без списка файлов, затем файлы по одному

Страница сначала отправляет `POST /api/v1/folders`:

```
{ protocolVersion, messageId, type: "folder.offer", folderId, name, fileCount, totalBytes }
```

`folderId` создаёт страница, по тем же правилам, что и `transferId`. После принятия страница по очереди хеширует каждый файл и предлагает его обычным `POST /api/v1/files` с одним элементом и двумя новыми необязательными полями: `folderId` и `relativePath` (например `2024/лето/1.jpg`). `displayName` — последняя часть пути. Когда файлы кончились, страница отправляет `POST /api/v1/folders/{folderId}/finish` с числом файлов, которые она не смогла прочитать.

**Альтернатива: полный список файлов с суммами в заявке.** Отвергнута по двум причинам:
- пришлось бы хешировать до 20 ГиБ до того, как телефон хотя бы спросит пользователя;
- список из 2000 путей не помещается в предел управляющего JSON в 64 КиБ.

Заявленных `fileCount` и `totalBytes` хватает для вопроса пользователю и для проверки пределов. Телефон отклоняет файл сверх заявленного числа или объёма.

**Прочие маршруты:**
- `DELETE /api/v1/folders/{folderId}` отменяет папку;
- `POST /api/v1/folders/{folderId}/retry` снова открывает папку для не сохранённых файлов;
- событие WebSocket `folder.progress`: `{folderId, status, fileCount, savedCount, failedCount, bytesDone, totalBytes, currentPath}`;
- `file.snapshot` получает массив `folders`, чтобы переподключившаяся страница восстановила карточку.

Все маршруты проходят те же проверки Host, Origin, сессии и размера тела, что и файловые. Идемпотентность по `messageId` та же.

### 2. Папка — одно место в очереди, законченные файлы сворачиваются

В `FileTransferCoordinator` появляется `FolderTransferState`: владелец-сессия, имя, заявленные число и объём, счётчики, статус и аренда места сохранения. Статусы: `CONNECTING`, `TRANSFERRING`, `COMPLETED`, `CANCELLED`, `STOPPED` (нет места, место недоступно) и `INTERRUPTED` (сессия потеряна, сервер остановлен).

- `FileTransferScheduler` ставит папку в очередь направления «браузер → телефон» как один элемент. Пока папка активна, активным файлом этого направления может быть только текущий файл папки.
- Файл папки создаётся сразу в `TRANSFERRING`, с арендой папки, без собственного `CONNECTING`.
- Когда файл закончился, его результат попадает в счётчики папки, а сам элемент удаляется из списка передач. Поэтому папка занимает одно место из 100, сколько бы файлов в ней ни было.
- Отдельные файлы, предложенные во время папки, ждут в очереди как сейчас.

### 3. Папка на телефоне: создание, пути, совпадения

При принятии `FolderDestination` создаёт верхнюю папку в корне выбранного дерева через `DocumentsContract.createDocument(..., MIME_TYPE_DIR, name)`.

- **Имя верхней папки.** Совпадение проверяется по списку корня, как у файлов, получается «Фото (2)». Некоторые провайдеры сами переименовывают папку при совпадении, поэтому после создания фактическое имя читается обратно. Оно идёт в итог и историю.
- **Подпапки.** Создаются лениво, при первом файле в них. Документ каждой созданной подпапки запоминается в таблице «относительный путь → documentId», которая живёт, пока жива папка.
- **Проверка пути,** до всякой записи:
  - путь делится по `/`, обратная косая черта считается разделителем;
  - отклоняются абсолютный путь, пустые части, `.` и `..`, управляющие символы и символы смены направления текста, путь длиннее 1024 символов, часть длиннее 255 символов, глубина больше 16;
  - каждая часть очищается `SafeFilenameResolver.normalize`, а совпадения внутри одной папки решает `resolveCollision` по списку этой папки и по уже созданным в ней именам.
- **Где лежат части.** `PartialDocumentManager` и `ContentResolverPartialDocumentProvider` получают родительский документ: корень дерева для отдельных файлов, нужную подпапку для файлов папки. Незавершённая часть `*.devicebridge-partial` создаётся рядом с будущим файлом.

**Альтернатива: `DocumentFile`.** Отвергнута. `DocumentFile.findFile` на каждый файл перебирает папку заново, а в проекте уже есть свой слой над `DocumentsContract`.

### 4. Ключ продолжения для файла папки

`PartialUploadKey` не меняется по составу. Для файла папки `displayName` — относительный путь, а `treeUri` — URI документа верхней папки. Уникальный индекс `partial_uploads` остаётся верным, схема не меняется.

Продолжение работает в пределах одной папки, то есть одного запуска сервера. Если папка закончилась как `INTERRUPTED`, незавершённая часть текущего файла удаляется, а не сохраняется: продолжить её уже некому.

### 5. Решение по папке

- **Вручную.** Карточка папки на экране передач с «Принять в выбранную папку», «Принять и выбрать папку» и «Отклонить». Выбор места через `OpenDocumentTree` происходит один раз, аренда регистрируется под `folderId`.
- **Автоматически.** `TrustedAutoAcceptController` применяет к папке то же правило, что и к файлу: запомненный браузер, включён автоприём, место выбрано.
- **Из уведомления.** `NotificationAcceptedTransfers` принимает `folderId`.

Файлы папки этими механизмами не рассматриваются: они наследуют решение папки.

### 6. Страница: сбор папки

- **«Выбрать папку».** Отдельный скрытый `<input type="file" webkitdirectory>`. У каждого `File` есть `webkitRelativePath`, первая часть пути — имя папки, она отрезается.
- **Перетаскивание.** В обработчике `drop` синхронно, до первого `await`, берутся `item.webkitGetAsEntry()` для всех элементов. Затем каталоги обходятся рекурсивно через `DirectoryReader.readEntries`. Его вызывают, пока не вернётся пустой массив: Chrome отдаёт записи порциями по 100.
- **Фильтры.** Отбрасываются служебные имена без учёта регистра. Пустые папки не попадают в список сами. Файлы больше действующего предела откладываются в список «не будут отправлены» и показываются в карточке, до пяти имён и число остальных.
- **Пределы** 2000 файлов, 20 ГиБ и 16 уровней проверяются по итоговому списку. Превышение делает папку в черновике неотправляемой с понятной причиной.
- **Долгий сбор.** Пока идёт обход большой папки, карточка показывает «Собираем папку… N файлов».

Черновик хранит папку как `FolderDraft {name, files: [{file, relativePath}], tooLarge: [...], error?}`.

### 7. Страница: передача

`fileTransferController` отправляет папку в таком порядке:

1. Заявка, затем ожидание `folder.progress` со статусом `TRANSFERRING`.
2. Для каждого файла по очереди: потоковый SHA-256, предложение файла, `upload-offset`, отправка тела.
3. Если файл не читается (`NotReadableError`, файл удалён), он записывается в ошибки на странице и передача идёт дальше.
4. После последнего файла `finish`.

При обрыве связи на середине файла страница после восстановления связи повторяет этот файл через существующий повтор с продолжением, до трёх раз, и идёт дальше. Отмена на карточке вызывает `DELETE /api/v1/folders/{id}`. «Повторить» вызывает `retry` и отправляет только не сохранённые файлы. Страница помнит их по ответам телефона на каждый файл.

### 8. История

- `HistoryKind.FOLDER`.
- Room версии 3. `MIGRATION_2_3` добавляет в `history_records` два столбца `folder_file_count INTEGER` и `folder_saved_count INTEGER`, допускающие NULL.
- `fileDisplayName` хранит фактическое имя созданной папки, `fileSizeBytes` — общий размер, `fileMimeType` — `inode/directory`, `fileSha256` — NULL.
- Запись создаётся при любом конечном статусе папки. `operationId` строится из `folderId`, поэтому после «Повторить» существующий `replace` обновляет ту же запись.
- Схема `3.json` экспортируется, миграция проверяется в `DeviceBridgeMigrationTest`.

### 9. Уведомления

- `EventNotificationPlanner` видит папку в `CONNECTING` и показывает `EventNotice.IncomingFolder(sessionId, folderId, name, fileCount, totalBytes, acceptable)` с «Принять» и «Отклонить».
- Конечный статус папки даёт `EventNotice.FolderResult`.
- Файлы папки исключаются из `IncomingFiles` и из итогов по файлам.
- Правила «не дублировать то, что на экране» и скрытия на экране блокировки те же.

### 10. Экран телефона

`FileUiState` получает элементы-папки. Карточка папки на экране передач показывает решение, прогресс, текущий файл, отмену и итог. `ActiveFileTransfersSection` на главном экране показывает папку одной строкой. `HistoryScreen` показывает запись папки с «N из M файлов».

## Risks / Trade-offs

- **[Каждый файл читается дважды: для суммы и для отправки]** → Так работает и сейчас. Суммы считаются по одному файлу перед отправкой, поэтому передача начинается сразу. Параллельное хеширование — будущая оптимизация.
- **[Провайдер хранилища медленно создаёт папки или сам меняет имя]** → Подпапки создаются один раз и запоминаются. Фактическое имя читается обратно после создания.
- **[Длинные имена обрезаются до 120 символов и могут совпасть]** → Совпадения после обрезки решаются суффиксом « (2)», как у файлов.
- **[`webkitGetAsEntry` и `webkitdirectory` нестандартны]** → Они есть в Chrome, Edge, Firefox и Safari. Если API нет, кнопка папки скрыта, а перетащенная папка даёт понятную ошибку вместо непригодного файла.
- **[Папка прервана перезапуском сервера]** → Итог «Прервано» с числом сохранённых файлов. Сохранённые файлы остаются, недошедшие можно отправить новой папкой. Так записано в спецификации.
- **[Страница заявила меньше файлов или меньший объём, чем прислала]** → Телефон отклоняет лишнее. Заявка не даёт записать больше заявленного.
- **[20 ГиБ — долгая передача]** → Общий прогресс и текущий файл на обеих сторонах. Автоостановка сервера не срабатывает, пока идёт передача (как сейчас).

## Migration Plan

- Room 2 → 3: два столбца с NULL, существующие записи не трогаются. Проверка — миграционный тест.
- Протокол расширяется совместимо: старые поля не меняются, новые поля и маршруты необязательны для отдельных файлов. Страница и приложение выходят вместе, в одном APK.
- Откат: версия приложения без папок не понимает базу версии 3. Понижение версии не поддерживается, как и раньше.
