## 1. Android: путь внутри папки и хранилище

- [ ] 1.1 Реализовать `FolderPathValidator`. Он делит путь по `/` (обратная косая черта тоже разделитель) и отклоняет:
  - абсолютный путь, пустые части, `.` и `..`;
  - управляющие символы и символы смены направления текста;
  - путь длиннее 1024 символов, часть длиннее 255, глубину больше 16.

  Каждая часть очищается `SafeFilenameResolver.normalize`. Проверка: JVM-тесты на каждое правило, на `../секрет.txt`, `/etc/hosts`, `a//b`, `C:\x`, имена Windows `CON`, обратную косую черту и кириллицу
- [ ] 1.2 Дать `ContentResolverPartialDocumentProvider` и `PartialDocumentManager` родительский документ вместо постоянного корня дерева. Отдельные файлы по-прежнему пишутся в корень. Проверка: существующие `PartialDocumentManagerTest` и `ResumableUploadPreparerTest` проходят без изменений поведения, новый тест пишет часть и готовый файл в подпапку
- [ ] 1.3 Реализовать `FolderDestination`:
  - верхняя папка в корне дерева через `createDocument(MIME_TYPE_DIR)` с суффиксом « (2)», « (3)» при совпадении, фактическое имя читается обратно;
  - ленивое создание подпапок с таблицей «путь → documentId»;
  - совпадения внутри одной папки без учёта регистра и после очистки получают « (2)».

  Проверка: JVM-тесты на поддельном провайдере (новая папка, совпадение имени, провайдер сам переименовал, `Отчёт.pdf` и `отчёт.pdf`, повторный файл в уже созданной подпапке не создаёт её снова) и instrumented-тест на эмуляторе API 37 с настоящим деревом SAF в `Download`
- [ ] 1.4 Ключ продолжения для файла папки: `displayName` — относительный путь, `treeUri` — URI верхней папки. При `INTERRUPTED` незавершённая часть текущего файла удаляется. Проверка: `ResumableUploadPreparerTest` на продолжение файла из подпапки и на удаление части при прерывании папки

## 2. Android: состояние папки и очередь

- [ ] 2.1 Добавить `FolderTransferState` в `FileTransferCoordinator`:
  - статусы `CONNECTING`, `TRANSFERRING`, `COMPLETED`, `CANCELLED`, `STOPPED`, `INTERRUPTED`;
  - заявленные число и объём, счётчики сохранённых и ошибок, текущий путь, владелец-сессия;
  - `createFolder`, `approveFolder(folderId, destinationId)`, `declineFolder`, `cancelFolder`, `finishFolder(unreadable)`, `retryFolder`.

  Проверка: JVM-тесты переходов, идемпотентность по `messageId`, отказ чужой сессии
- [ ] 2.2 Файл папки создаётся сразу в `TRANSFERRING` с арендой папки. Файл сверх заявленного числа или объёма, файл неактивной или чужой папки отклоняется. Законченный файл уходит в счётчики и удаляется из списка передач. Проверка: JVM-тест, где папка из 2000 файлов проходит через координатор с `maxItems = 100`, и тесты на одиннадцатый файл при заявленных 10 и на превышение объёма
- [ ] 2.3 `FileTransferScheduler` ставит папку одним элементом очереди «браузер → телефон». Отдельные файлы ждут конца папки. Проверка: `FileTransferSchedulerTest` на порядок «файл, папка, файл»
- [ ] 2.4 Ошибки: ошибка файла увеличивает `failedCount` и не останавливает папку. `InsufficientSpace` и недоступное место дают `STOPPED`. Потеря сессии и остановка сервера дают `INTERRUPTED`. Отмена удаляет часть текущего файла и сохраняет готовые файлы. Проверка: JVM-тесты на каждый путь, включая итог «Отменено: сохранено 60 из 120»
- [ ] 2.5 Решение по папке: аренда `FileDestinationLeaseRegistry` под `folderId`, `TrustedAutoAcceptController` для папок, `NotificationAcceptedTransfers` принимает `folderId`. Файлы папки не проходят эти механизмы. Проверка: `TrustedAutoAcceptControllerTest` на автоприём папки от запомненного браузера и на отказ без места сохранения
