## Purpose

Передача папки целиком с компьютера на телефон: одно решение на телефоне, та же структура подпапок внутри выбранного места сохранения, безопасные пути, общий прогресс, отмена, повтор и итог папки.

## ADDED Requirements

### Requirement: Папка передаётся одной операцией с одним решением на телефоне

Browser MUST предлагать папку телефону одним предложением: имя папки, число файлов и их общий размер. Телефон MUST показывать пользователю одно решение на всю папку и MUST NOT принимать содержимое файлов папки до этого решения. После принятия файлы этой папки MUST NOT требовать отдельных решений. Папку MUST предлагать только действующая авторизованная browser session, и только она MUST передавать файлы этой папки.

#### Scenario: Browser предлагает папку

- **WHEN** пользователь подтверждает отправку папки «Фото» из 120 файлов общим размером 3,4 ГиБ
- **THEN** телефон показывает одно решение «Принять папку "Фото": 120 файлов, 3,4 ГиБ?»
- **AND** ни один байт файлов не принимается до решения

#### Scenario: Папка принята

- **WHEN** пользователь принял папку
- **THEN** все её файлы передаются без новых вопросов

#### Scenario: Папка отклонена

- **WHEN** пользователь отклонил папку
- **THEN** на телефоне ничего не создаётся
- **AND** browser показывает, что папка отклонена

#### Scenario: Файл папки от чужой session

- **WHEN** другая browser session предлагает файл с идентификатором чужой папки
- **THEN** телефон отклоняет файл
- **AND** папка продолжает передачу как прежде

### Requirement: Пределы папки проверяются до передачи

Папка MUST содержать не больше 2000 файлов, не больше 21 474 836 480 байт (20 ГиБ) в сумме и не больше 16 уровней вложенности. Каждый файл MUST укладываться в действующий предел одного файла. Относительный путь файла MUST быть не длиннее 1024 символов, а каждая его часть не длиннее 255 символов. Телефон MUST проверять заявленные число файлов и общий размер при предложении папки и MUST отклонять файл, который превышает заявленное число файлов или заявленный общий размер папки.

#### Scenario: Папка в пределах

- **WHEN** browser предлагает папку из 2000 файлов общим размером 20 ГиБ с вложенностью 16 уровней
- **THEN** телефон принимает предложение к решению

#### Scenario: Заявлено больше 2000 файлов

- **WHEN** browser предлагает папку из 2001 файла
- **THEN** телефон отклоняет предложение с понятной причиной
- **AND** решение пользователю не показывается

#### Scenario: Файлов больше, чем заявлено

- **WHEN** browser заявил 10 файлов и предлагает одиннадцатый
- **THEN** телефон отклоняет одиннадцатый файл
- **AND** уже сохранённые файлы остаются

### Requirement: Папка создаётся внутри места сохранения без слияния

При принятии папки телефон MUST создать новую папку с именем предложенной папки внутри выбранного места сохранения и воссоздавать в ней подпапки по относительным путям файлов. Если папка с таким именем уже есть, телефон MUST создать новую папку с суффиксом « (2)», « (3)» и так далее и MUST NOT записывать файлы в существующую папку.

#### Scenario: Папки с таким именем нет

- **WHEN** пользователь принял папку «Фото», а в месте сохранения такой папки нет
- **THEN** телефон создаёт папку «Фото»
- **AND** файл `2024/лето/1.jpg` сохраняется как `Фото/2024/лето/1.jpg`

#### Scenario: Папка с таким именем уже есть

- **WHEN** в месте сохранения уже есть папка «Фото»
- **THEN** телефон создаёт папку «Фото (2)» и сохраняет файлы в неё
- **AND** содержимое существующей папки «Фото» не меняется

### Requirement: Пути внутри папки не выводят за её пределы

Телефон MUST проверять каждую часть относительного пути файла. Путь MUST NOT быть абсолютным и MUST NOT содержать пустых частей, частей `.` и `..`, управляющих символов и символов смены направления текста. Недопустимые для файловой системы символы и зарезервированные имена MUST заменяться так же, как в именах отдельных файлов. Если две части пути в одной папке совпадают без учёта регистра или после замены символов, вторая MUST получить суффикс « (2)», а не перезаписать первую. Телефон MUST NOT записывать ничего за пределами созданной папки.

#### Scenario: Путь пытается выйти из папки

- **WHEN** browser предлагает файл папки с путём `../секрет.txt` или `/etc/hosts`
- **THEN** телефон отклоняет этот файл
- **AND** ничего не записывается вне созданной папки

#### Scenario: Имена совпадают без учёта регистра

- **WHEN** в одной папке есть файлы `Отчёт.pdf` и `отчёт.pdf`
- **THEN** оба сохраняются, второй как `отчёт (2).pdf`

### Requirement: Файлы папки передаются по очереди с проверкой и продолжением

Файлы принятой папки MUST передаваться по одному. Каждый файл MUST проходить ту же проверку контрольной суммы, что и отдельный файл. Файл от 8 МиБ, передача которого оборвалась, MUST продолжаться с сохранённого места по тем же правилам, что и отдельный файл, в тот же путь внутри папки. Папка MUST занимать одно место в очереди передач: законченные файлы папки MUST NOT расходовать предел числа передач в очереди, а отдельные файлы MUST ждать, пока папка не закончится.

#### Scenario: Большая папка не упирается в предел очереди

- **WHEN** принята папка из 2000 файлов
- **THEN** все 2000 файлов передаются
- **AND** после папки browser может отправить отдельные файлы

#### Scenario: Обрыв посреди файла

- **WHEN** связь оборвалась на середине файла размером 50 МиБ, а та же страница снова подключилась
- **THEN** этот файл продолжается с сохранённого места
- **AND** следующие файлы папки передаются после него

### Requirement: Прогресс папки наблюдаем на обеих сторонах

Телефон и browser MUST показывать для папки число сохранённых файлов из общего, переданный объём из общего и имя текущего файла. Обновления прогресса папки MUST NOT приходить чаще, чем обновления прогресса отдельного файла.

#### Scenario: Идёт передача

- **WHEN** сохранено 40 файлов из 120 и передаётся `2024/лето/41.jpg`
- **THEN** обе стороны показывают «40 из 120», переданный объём и имя `41.jpg`

### Requirement: Отмена останавливает всю папку

Отмена папки на любой стороне MUST остановить текущий файл и удалить его незавершённую часть, MUST NOT начинать оставшиеся файлы и MUST оставить уже сохранённые файлы на телефоне. Итог отменённой папки MUST называть число сохранённых файлов.

#### Scenario: Отмена на середине

- **WHEN** пользователь отменил папку после 60 сохранённых файлов из 120
- **THEN** передача останавливается на обеих сторонах
- **AND** 60 файлов остаются в папке на телефоне
- **AND** итог «Отменено: сохранено 60 из 120»

### Requirement: Ошибка файла не останавливает папку

Ошибка отдельного файла (файл нельзя прочитать, не совпала контрольная сумма, недопустимый путь) MUST NOT останавливать остальные файлы папки. Нехватка места на телефоне и недоступное место сохранения MUST останавливать папку сразу. Итог папки MUST называть число сохранённых файлов, общее число и число ошибок. «Повторить» MUST отправлять только не сохранённые файлы в ту же созданную папку и MUST быть доступно, пока страница, с которой отправлена папка, открыта и сервер не перезапускался.

#### Scenario: Два файла с ошибкой

- **WHEN** из 120 файлов два не удалось прочитать на компьютере
- **THEN** остальные 118 сохраняются
- **AND** итог «118 из 120, 2 с ошибкой» с кнопкой «Повторить»

#### Scenario: Повтор

- **WHEN** пользователь нажал «Повторить»
- **THEN** передаются только два не сохранённых файла, в ту же папку на телефоне

#### Scenario: Закончилось место

- **WHEN** на телефоне закончилось место на 30-м файле
- **THEN** папка останавливается
- **AND** итог называет нехватку места и число сохранённых файлов

#### Scenario: Сервер перезапущен посреди папки

- **WHEN** сервер остановлен во время передачи папки
- **THEN** папка заканчивается с итогом «Прервано» и числом сохранённых файлов
- **AND** сохранённые файлы остаются, а недошедшие можно отправить только новой папкой
