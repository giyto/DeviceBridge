## Why

DeviceBridge работает по `http://IP:порт`, поэтому трафик в локальной сети не шифруется. Любой участник той же Wi-Fi может его прочитать или подменить. Кроме того, для браузера такая страница — незащищённый контекст, и ему недоступны автокопирование в буфер, системные уведомления и установка как приложения. Шифрование самим приложением поверх HTTP проблему не решает: JavaScript страницы тоже приходит по HTTP и может быть подменён. Поэтому нужен настоящий HTTPS без постоянных предупреждений браузера.

## What Changes

- Добавляется необязательный «Защищённый режим» в настройках Android. По умолчанию он выключен, и обычный HTTP-режим работает как раньше.
- В защищённом режиме телефон создаёт собственный корневой сертификат (локальный центр сертификации). Его закрытый ключ неэкспортируемый и хранится в AndroidKeyStore. Name constraints ограничивают сертификат частными IPv4-диапазонами и именем `devicebridge.local`, поэтому им нельзя подписать чужой сайт.
- Сертификат сервера подписывается этим корнем, выписывается на текущие LAN-адреса телефона и перевыпускается автоматически при смене адреса или приближении срока. Повторно устанавливать что-то на компьютер при этом не нужно.
- Сервер принимает HTTPS на том же порту, что и раньше. Обычный HTTP-запрос на этот порт получает только страницу установки сертификата и переход на `https://`. API, WebSocket и файлы по HTTP в этом режиме недоступны.
- Страница установки даёт скачать сертификат и показывает пошаговую инструкцию для Windows, macOS, Chrome, Edge и Firefox. Телефон показывает отпечаток сертификата, чтобы сверить его в окне импорта: скачанный по HTTP файл мог быть подменён.
- Адрес на телефоне, в уведомлении и на плитке показывается как `https://IP:порт`. Проверки `Host`/`Origin` принимают только схему текущего режима.
- В web-интерфейсе предупреждение о незашифрованном HTTP заменяется пометкой о защищённом соединении, если страница открыта по HTTPS. Автокопирование в буфер начинает работать само, так как страница становится защищённым контекстом.
- В настройках появляется действие «Сбросить сертификат»: создаётся новый корень, старый перестаёт действовать, а пользователю объясняется, как удалить старый сертификат с компьютера.
- Сохранённые данные браузера привязаны к адресу страницы, поэтому после перехода на HTTPS браузер один раз подключается заново по коду. Запомненные на телефоне браузеры при этом не отзываются.

Вне объёма (отдельные будущие change): системные уведомления на компьютере, установка страницы как приложения (PWA), mDNS-имя `devicebridge.local`, сертификаты публичного центра через собственный домен.

## Capabilities

### New Capabilities

- `https-secure-mode`: включение и выключение защищённого режима, локальный корневой сертификат и его ограничения, выпуск и перевыпуск сертификата сервера, приём TLS и обычного HTTP на одном порту, страница установки сертификата со сверкой отпечатка, сброс сертификата, сохранение реального адреса клиента.

### Modified Capabilities

- `server-lifecycle`: показываемый пользователю URL использует схему текущего режима (`https://` в защищённом режиме).
- `browser-web-interface`: предупреждение о незашифрованном локальном HTTP показывается только на HTTP-странице, а на HTTPS заменяется пометкой о защищённом соединении.
- `mvp-release-readiness`: LAN-only модель допускает заявление о шифровании только в защищённом режиме и только когда страница действительно открыта по HTTPS.

## Impact

- **Android, сервер:** `KtorServerRuntimeFactory` (запуск и остановка TLS-приёмника рядом с CIO, адрес клиента вместо `call.request.local.remoteHost`), новый пакет `data/tls` (корень, сертификат сервера, хранение, TLS-приёмник), `ServerEndpoint.url`, проверки `Origin` в `SessionRequestSecurityPolicy` и `WebRoutes`, новый маршрут страницы установки и скачивания сертификата.
- **Android, UI:** `DeviceSettings` и хранилище настроек (флаг режима), `SettingsScreen` (переключатель, отпечаток, сброс), отображение адреса на главном экране, в уведомлении и на плитке.
- **Web:** `securityWarningController` и вёрстка предупреждения, новая страница установки сертификата; `clipboardWriter` и `sessionEventSocketClient` уже учитывают защищённый контекст и `wss:`.
- **Зависимости:** BouncyCastle (`bcpkix`/`bcprov`) для построения X.509 с name constraints; размер APK проверяется после R8. Ktor CIO 3.5.2 не поддерживает TLS на сервере, поэтому TLS делается платформенным `SSLServerSocket`, без смены движка.
- **Тесты:** JVM (сертификаты, ограничения, перевыпуск, TLS-приёмник, адрес клиента), web (ветки для HTTPS), E2E в Chrome с доверенным тестовым корнем, замер скорости больших файлов через TLS.
