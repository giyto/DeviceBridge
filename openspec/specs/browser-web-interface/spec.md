# browser-web-interface Specification

## Purpose

Определить наблюдаемое поведение встроенного браузерного интерфейса DeviceBridge, который поставляется внутри Android APK, работает без интернета и честно показывает доступность телефона до появления pairing и передачи данных.

## Requirements

### Requirement: Web shell поставляется внутри Android APK

Android-приложение MUST содержать собранную корневую HTML-страницу и все необходимые ей статические ресурсы. Локальный сервер MUST отдавать страницу через `GET /`, а её ресурсы — только из содержимого установленного APK.

#### Scenario: Браузер открывает встроенную страницу

- **WHEN** пользователь открывает корневой адрес запущенного DeviceBridge в браузере компьютера
- **THEN** сервер возвращает HTML со статусом HTTP 200 и корректным `Content-Type`
- **AND** браузер загружает связанные CSS и JavaScript из того же origin

#### Scenario: Запрошен отсутствующий ресурс

- **WHEN** браузер запрашивает путь, которого нет среди встроенных web assets
- **THEN** сервер возвращает HTTP 404
- **AND** запрос не может прочитать произвольный файл приложения или устройства

### Requirement: Web assets имеют воспроизводимую версию

Web build MUST создавать детерминированный набор assets из зафиксированных исходников и lock-файла. Имена изменяемых CSS и JavaScript MUST содержать content hash, а HTML MUST ссылаться только на assets текущей сборки.

#### Scenario: Повторная сборка без изменения входов

- **WHEN** web build дважды выполняется с одинаковыми исходниками, lock-файлом и поддерживаемой версией Node.js
- **THEN** относительные пути и содержимое созданных web assets совпадают

#### Scenario: Web assets включаются в Android-сборку

- **WHEN** разработчик собирает debug или release APK через Gradle
- **THEN** актуальная версия web shell автоматически создаётся до упаковки Android assets
- **AND** APK содержит корневой HTML и все файлы, на которые он ссылается

### Requirement: Web shell работает без внешних ресурсов

Страница MUST работать без доступа к интернету и MUST NOT загружать внешние скрипты, стили, шрифты, изображения, аналитику или телеметрию. Runtime-запросы web shell MUST быть ограничены same-origin маршрутами DeviceBridge.

#### Scenario: Интернет недоступен

- **WHEN** компьютер и телефон соединены локально, но не имеют доступа к интернету
- **THEN** страница полностью загружается из Android-приложения
- **AND** отображение статуса соединения не требует внешнего backend

#### Scenario: Проверяется сетевая активность страницы

- **WHEN** разработчик открывает страницу и проверяет браузерные запросы
- **THEN** каждый запрос направлен тому же origin, с которого получен HTML
- **AND** service worker не регистрируется

### Requirement: Страница честно отображает доступность локального web server

Web shell MUST проверять доступность совместимой версии локального web server через same-origin `GET /web-manifest.json`. Manifest MUST считаться web asset, содержать только версии протокола и web assets и MUST NOT содержать токены, идентификаторы устройства или другие секреты. Защищённый `/api/v1/status` MUST NOT становиться публичным до реализации pairing и session token.

#### Scenario: Локальный web server доступен

- **WHEN** `/web-manifest.json` возвращает успешный совместимый ответ
- **THEN** страница показывает, что DeviceBridge доступен
- **AND** отображает версию протокола и версию web assets

#### Scenario: Статус недоступен

- **WHEN** запрос manifest завершается сетевой ошибкой, timeout или несовместимым ответом
- **THEN** страница показывает понятное состояние потери соединения
- **AND** предоставляет ограниченный автоматический retry и явное действие повторной проверки

#### Scenario: Неавторизованный API статуса не опубликован

- **WHEN** браузер без session token запрашивает `/api/v1/status`
- **THEN** сервер не возвращает сведения о состоянии устройства
- **AND** публичная проверка web shell использует только `/web-manifest.json`

### Requirement: Web routes ограничены локальным origin

Сервер MUST проверять допустимый `Host` и, когда заголовок `Origin` присутствует, принимать только same-origin запрос. Сервер MUST NOT возвращать разрешающий сторонние origins CORS-заголовок.

#### Scenario: Same-origin запрос разрешён

- **WHEN** web asset запрошен с допустимым `Host` без `Origin` или с соответствующим same-origin `Origin`
- **THEN** сервер возвращает запрошенный ресурс
- **AND** ответ не содержит permissive CORS

#### Scenario: Чужой Host или Origin отклонён

- **WHEN** запрос содержит недопустимый `Host` или сторонний `Origin`
- **THEN** сервер возвращает HTTP 403
- **AND** не раскрывает содержимое web asset

### Requirement: Страница загружается в установленный лимит

После установления TCP-соединения встроенная страница MUST загрузить локальный HTML и обязательные assets не более чем за пять секунд в поддерживаемой тестовой конфигурации.

#### Scenario: Измеряется полная загрузка web shell

- **WHEN** браузер открывает DeviceBridge в тестовой локальной конфигурации после установления TCP-соединения
- **THEN** HTML и обязательные assets завершают загрузку не позднее пяти секунд

### Requirement: Пользователь видит ограничение локального HTTP

Web shell MUST явно и понятным языком сообщать, что локальный HTTP не шифрует трафик и DeviceBridge следует использовать только в доверенной домашней или личной сети.

#### Scenario: Открыта корневая страница

- **WHEN** пользователь открывает web shell
- **THEN** на странице видимо предупреждение о незашифрованном локальном соединении
- **AND** пользователю рекомендовано не передавать чувствительные данные через публичный или чужой Wi-Fi

### Requirement: Недоступные функции не имитируют готовую работу

До реализации последующих changes web shell MUST NOT позволять выполнить pairing, отправку текста, загрузку или скачивание файлов. Интерфейс MUST явно объяснять, что подключение и передача данных появятся на следующих этапах.

#### Scenario: Пользователь открывает web shell третьего этапа

- **WHEN** страница успешно загружена и телефон доступен
- **THEN** пользователь видит статус соединения и информацию об этапе
- **AND** на странице нет работающих форм pairing, текста или файловых операций
- **AND** HTTP retry не обозначается как готовая WebSocket-сессия или WebSocket reconnect

### Requirement: Интерфейс адаптируется к браузерному окну и системной теме

Web shell MUST сохранять читаемость и основные действия при ширине viewport от 360 до 1920 пикселей и MUST поддерживать светлую и тёмную цветовую схему браузера.

#### Scenario: Узкое и широкое окно

- **WHEN** страница отображается при ширине 360, 768 или 1920 пикселей
- **THEN** основной контент не требует горизонтальной прокрутки
- **AND** статус и действие повторной проверки остаются видимыми и читаемыми

#### Scenario: Меняется системная цветовая схема

- **WHEN** браузер сообщает светлую или тёмную схему через системные настройки
- **THEN** страница применяет соответствующую тему
- **AND** текст и интерактивные элементы сохраняют достаточный контраст

### Requirement: Web shell доступен с клавиатуры и понятен вспомогательным технологиям

Документ MUST использовать корректную структуру заголовков, landmarks, доступные названия и нативные интерактивные элементы. Состояние соединения MUST быть доступно без опоры только на цвет.

#### Scenario: Навигация без мыши

- **WHEN** пользователь перемещается по странице клавишей Tab и активирует элементы с клавиатуры
- **THEN** фокус видим
- **AND** действие повторной проверки доступно и имеет понятное название

#### Scenario: Статус изменяется

- **WHEN** состояние меняется с проверки на доступность или ошибку
- **THEN** изменение представлено текстом
- **AND** вспомогательная технология может определить актуальное состояние

### Requirement: Web shell поддерживает целевые desktop-браузеры

Собранная страница MUST работать в актуальных стабильных Chrome и Edge на Windows 10 и Windows 11 без установки расширения, PWA или отдельной программы.

#### Scenario: Проверка в Chrome и Edge

- **WHEN** один адрес DeviceBridge открывается в целевой версии Chrome или Edge
- **THEN** оба браузера загружают одинаковую версию web assets
- **AND** одинаково отображают статус и действие повторной проверки
