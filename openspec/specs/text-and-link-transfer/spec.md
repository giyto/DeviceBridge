# text-and-link-transfer Specification

## Purpose
Определить безопасную, авторизованную и проверяемую передачу текста и HTTP(S)-ссылок между Android host и выбранной browser session в пределах текущего запуска DeviceBridge.

## Requirements

### Requirement: Текст передаётся только через активную browser session

DeviceBridge MUST передавать текст и ссылки только между Android host и действующей авторизованной browser session. Отправка с телефона MUST иметь явно выбранную session-получателя и MUST NOT неявно рассылать содержимое остальным подключённым браузерам.

#### Scenario: Android отправляет выбранному браузеру

- **WHEN** пользователь выбирает активную browser session, проверяет предпросмотр и подтверждает отправку
- **THEN** элемент получает только выбранная session
- **AND** другие активные sessions не получают содержимое

#### Scenario: Browser отправляет на телефон

- **WHEN** авторизованный browser client отправляет допустимый текст через защищённый маршрут
- **THEN** Android host показывает один входящий элемент с указанием отправившей session
- **AND** другие browser sessions не получают копию сообщения

#### Scenario: Session отсутствует или отозвана

- **WHEN** отправитель не имеет действующей session либо выбранная session уже отключена
- **THEN** передача не начинается
- **AND** интерфейс показывает понятное состояние повторного подключения или выбора другого браузера

### Requirement: Содержимое и размер строго валидируются

DeviceBridge MUST принимать непустой UTF-8 текст размером не более 100 КБ, измеренным после UTF-8 кодирования. Переносы строк и пользовательское содержимое MUST сохраняться как plain text; содержимое MUST NOT интерпретироваться как HTML или исполняемый код.

#### Scenario: Отправлен допустимый многострочный текст

- **WHEN** пользователь отправляет непустой plain text размером не более 100 КБ
- **THEN** получатель видит те же символы и переносы строк
- **AND** разметка HTML отображается как текст

#### Scenario: Превышен лимит

- **WHEN** UTF-8 представление содержимого превышает 100 КБ
- **THEN** отправка отклоняется до создания входящего элемента
- **AND** пользователь видит лимит и фактическую причину ошибки

#### Scenario: Содержимое пустое

- **WHEN** поле не содержит символов либо состоит только из пробельных символов
- **THEN** действие отправки недоступно или запрос отклоняется как некорректный
- **AND** пустой элемент не появляется у получателя

### Requirement: Ссылка определяется и открывается безопасно

DeviceBridge MUST классифицировать всё содержимое как ссылку только после успешного разбора всего значения как абсолютного URL со схемой `http` или `https`. Иные схемы и неоднозначные значения MUST оставаться обычным текстом. Полученная ссылка MUST открываться только после явного действия пользователя.

#### Scenario: Передана HTTPS-ссылка

- **WHEN** содержимое целиком является корректным абсолютным `https` URL
- **THEN** предпросмотр и входящая карточка показывают тип «Ссылка»
- **AND** получатель может явно скопировать или открыть её

#### Scenario: Передано опасное или неподдерживаемое значение

- **WHEN** содержимое использует `javascript`, `data`, `file` или другую неразрешённую схему либо не является единым абсолютным URL
- **THEN** DeviceBridge не предоставляет действие открытия как ссылки
- **AND** отображает содержимое только как безопасный plain text

#### Scenario: Ссылка получена

- **WHEN** допустимая ссылка появляется у получателя
- **THEN** DeviceBridge не открывает её автоматически
- **AND** переход возможен только после явного действия пользователя

### Requirement: Text protocol версионирован и идемпотентен

Каждая text-команда и WebSocket-событие MUST содержать поддерживаемые `protocolVersion`, `messageId`, `type` и `timestamp`; payload MUST иметь ограниченную схему с содержимым и вычисленным типом. Повтор команды с тем же `messageId` в той же session и server generation MUST возвращать согласованный результат и MUST NOT повторно доставлять уже принятую операцию.

#### Scenario: Browser отправляет корректную команду

- **WHEN** действующая session выполняет `POST /api/v1/text` с допустимым новым `messageId` и payload
- **THEN** сервер принимает ровно одну операцию и возвращает определённое подтверждение
- **AND** Android получает один входящий элемент

#### Scenario: Повторяется подтверждённый messageId

- **WHEN** тот же browser client повторяет команду с тем же `messageId` и тем же payload
- **THEN** сервер возвращает ранее определённый результат
- **AND** второй входящий элемент не создаётся

#### Scenario: MessageId повторён с другим payload

- **WHEN** в той же session повторно используется `messageId` с отличающимся содержимым
- **THEN** сервер отклоняет конфликт
- **AND** ранее принятый элемент не изменяется

#### Scenario: Версия протокола не поддерживается

- **WHEN** text-команда или событие содержит неизвестную major protocol version
- **THEN** получатель отклоняет сообщение с понятной version error
- **AND** пользовательское содержимое не доставляется

### Requirement: Доставка имеет наблюдаемые состояния и acknowledgement

DeviceBridge MUST показывать для исходящего элемента состояния подготовки, отправки, доставки или ошибки. Доставка Android → Browser MUST подтверждаться browser acknowledgement через авторизованный `/api/v1/events`; успешный HTTP-ответ Browser → Android MUST означать принятие элемента Android host, а не последующее копирование или открытие пользователем.

#### Scenario: Browser подтверждает входящий элемент

- **WHEN** выбранная browser session получила text event и приняла его в текущую ленту
- **THEN** browser отправляет acknowledgement с соответствующим `messageId`
- **AND** Android показывает исходящий элемент как доставленный

#### Scenario: Соединение потеряно до подтверждения

- **WHEN** WebSocket закрывается до acknowledgement
- **THEN** исходящий элемент не отмечается доставленным
- **AND** пользователь видит ошибку и явное действие повторной отправки после восстановления session

#### Scenario: Пользователь повторяет неуспешную отправку

- **WHEN** пользователь явно повторяет операцию после сетевой ошибки
- **THEN** DeviceBridge использует идемпотентный протокольный идентификатор либо новый идентификатор только для новой пользовательской операции
- **AND** уже подтверждённый элемент не дублируется у получателя

### Requirement: Текущая text-лента не становится постоянной историей

Android и web UI MUST показывать отправленные и полученные text items текущего server generation с отправителем, временем, направлением, типом и status. Полное содержимое и текущая лента MUST NOT сохраняться постоянно. После terminal результата Android MUST создать не более одной local history record с безопасными metadata и plain-text preview не длиннее 200 Unicode code points; trusted-browser state и Android backup MUST NOT содержать полный text payload.

#### Scenario: Пользователь просматривает текущую сессию
- **WHEN** в текущем server generation были переданы элементы
- **THEN** Android и соответствующая browser session показывают доступные им полные элементы и статусы
- **AND** каждый элемент различает направление и отправителя

#### Scenario: Browser восстанавливает ту же session после обновления страницы
- **WHEN** страница обновлена в той же вкладке и tab-scoped token остаётся действительным
- **THEN** после повторной авторизации events connection web UI получает ограниченный snapshot доступной текущей text-ленты
- **AND** элементы с уже известным messageId не дублируются

#### Scenario: Text operation получила terminal result
- **WHEN** операция получает delivered или failed
- **THEN** Android history сохраняет messageId, тип, направление, browser label, время, status и безопасный короткий preview
- **AND** повторный acknowledgement или идемпотентный request не создаёт вторую record

#### Scenario: Server lifecycle завершён
- **WHEN** пользователь останавливает сервер или generation завершается из-за ошибки сети или разрешения
- **THEN** незавершённые операции получают конечное состояние ошибки или отмены согласно transfer contract
- **AND** новый server generation не восстанавливает полное содержимое прежней text-ленты, но terminal history metadata остаются доступными

#### Scenario: History storage недоступен
- **WHEN** terminal text operation не удалось записать в local history
- **THEN** фактический delivery result не изменяется и payload повторно не отправляется
- **AND** Android показывает отдельную безопасную ошибку persistence без раскрытия полного текста в журнале

### Requirement: Android поддерживает явный ввод и системное действие Поделиться

Android UI MUST предоставлять поле ввода, явное действие вставки, распознанный тип, предпросмотр и подтверждение отправки. DeviceBridge MUST принимать `ACTION_SEND` с `text/plain` в предпросмотр, но MUST NOT отправлять shared text без выбора активной session и подтверждения пользователя и MUST NOT скрыто читать clipboard.

#### Scenario: Пользователь вводит текст в приложении

- **WHEN** активна хотя бы одна browser session и пользователь открывает действие «Текст»
- **THEN** Android показывает редактор, выбранного получателя, распознанный тип и предпросмотр
- **AND** передача начинается только после подтверждения

#### Scenario: Текст передан через системное меню

- **WHEN** другое Android-приложение вызывает `ACTION_SEND` с MIME type `text/plain`
- **THEN** DeviceBridge открывает предпросмотр полученного текста без автоматической отправки
- **AND** требует выбрать session и подтвердить действие

#### Scenario: Пользователь вставляет из clipboard

- **WHEN** пользователь нажимает явное действие вставки на открытом text-экране
- **THEN** Android запрашивает clipboard только в контексте этого действия
- **AND** приложение не наблюдает clipboard в фоне

### Requirement: Browser предоставляет безопасную text-форму и копирование

После авторизации web UI MUST предоставлять поле отправки и ленту входящих элементов текущей tab/session. Действие копирования MUST использовать Clipboard API только когда оно доступно и разрешено; иначе содержимое MUST оставаться выделяемым с понятной инструкцией ручного копирования.

#### Scenario: Browser отправляет текст

- **WHEN** пользователь вводит допустимое содержимое и подтверждает отправку
- **THEN** форма показывает ход и результат операции
- **AND** принятый Android host элемент отображается в ленте с направлением и статусом

#### Scenario: Clipboard API недоступен в локальном HTTP

- **WHEN** browser запрещает программное копирование из-за insecure context или permission
- **THEN** web UI не сообщает ложный успех
- **AND** показывает выделяемое содержимое и инструкцию ручного копирования

#### Scenario: Получено содержимое с HTML-разметкой

- **WHEN** text event содержит символы HTML или script-like текст
- **THEN** web UI отображает их как plain text
- **AND** не создаёт исполняемую разметку из пользовательского содержимого

### Requirement: Recoverable text failure сохраняет draft и идентичность операции

Если text или link operation не получила terminal acknowledgement из-за временного разрыва, UI MUST сохранить исходный draft и обозначить результат как uncertain или failed, а не delivered. Manual retry той же операции MUST повторно использовать исходный `messageId`; изменение содержимого MUST считаться новой операцией с новым identifier.

#### Scenario: Связь потеряна до acknowledgement

- **WHEN** отправитель передал text payload, но не получил terminal acknowledgement до разрыва session
- **THEN** item остаётся uncertain или failed и предоставляет retry только после восстановления session
- **AND** исходный текст остаётся доступен пользователю в текущем server generation

#### Scenario: Пользователь повторяет без изменения содержимого

- **WHEN** пользователь явно повторяет ту же text operation после восстановления session
- **THEN** отправитель использует исходный `messageId`
- **AND** уже принявший payload получатель возвращает прежний результат без второй записи в ленте

#### Scenario: Пользователь редактирует draft перед отправкой

- **WHEN** пользователь меняет содержимое uncertain или failed item и подтверждает отправку
- **THEN** DeviceBridge создаёт новую operation с новым `messageId`
- **AND** предыдущий item сохраняет собственный terminal или uncertain status

### Requirement: Text recovery action соответствует причине ошибки

Text UI MUST различать потерю session, превышение размера, пустой payload, неподдерживаемую ссылку и неподдерживаемую protocol version. Retry SHALL быть доступен только для причины, при которой повтор неизменённой операции может завершиться успешно.

#### Scenario: Payload превышает лимит

- **WHEN** текст больше установленного protocol limit
- **THEN** UI показывает лимит и предлагает сократить содержимое
- **AND** не показывает сетевой retry для неизменённого payload

#### Scenario: Session потеряна

- **WHEN** выбранная browser session закрыта до отправки
- **THEN** UI сохраняет draft и предлагает выбрать или восстановить получателя
- **AND** payload не перенаправляется другой session автоматически

### Requirement: Text session feed остаётся читаемой и управляемой

Android и web UI MUST представлять текущие text/link items в спокойной session feed с различимыми направлением, отправителем, временем, типом и status. Composer MUST оставаться в предсказуемой доступной области. Item actions MUST находиться внутри соответствующей карточки и MUST NOT перекрывать текст, ссылку или соседние controls при длинном содержимом, font scale или browser zoom.

#### Scenario: Длинная ссылка получена на Android

- **WHEN** link item содержит URL, который шире доступной карточки
- **THEN** отображение переносится или сокращается без изменения копируемого значения
- **AND** действия «Копировать» и «Открыть» остаются внутри карточки и доступны TalkBack

#### Scenario: Browser открыт с zoom 200 процентов

- **WHEN** text feed отображается при zoom 200 процентов или viewport 360 пикселей
- **THEN** composer, item status и actions остаются доступны без горизонтальной прокрутки страницы
- **AND** visual order совпадает с keyboard focus order

#### Scenario: Item ожидает доставку

- **WHEN** text operation находится в sending или uncertain state
- **THEN** карточка показывает текстовый status и только применимые actions без ложного success styling
- **AND** изменение status не перемещает focus пользователя автоматически
